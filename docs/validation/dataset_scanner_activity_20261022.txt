SCANNER LIVE ACTIVITY UPDATE — 22 October 2026

The previous Windows UI updated discovery only once per year, so a long network
folder traversal could appear stalled. The screenshot alone cannot establish
whether the user's actual Windows process is advancing. The real G: drive is
not accessible from this development environment.

The scanner now reports the folder BEFORE attempting directory enumeration,
and shows folders checked, files seen, project folders found and relevant files
found. Discovery still restricts years and excludes raw/statistics/generated
folders and links/junctions. It avoids unnecessary per-file network metadata
queries for irrelevant files. Unreadable folders remain explicit issues.

Later phases show the current project/mode, workbook or MAT read, original
feature rows, curated entries checked, selected-file verification, source
freshness checks, copying and copied-file verification. Byte counters represent
actual processed bytes, not an invented overall percentage. Dataset totals
become available only after discovery. Recent activity is bounded to 50 steps.

Elapsed time uses a monotonic clock. The progress-age clock is updated only by
worker progress, never by browser polling or a cancellation request. The UI
separately reports local-server responsiveness and whether the worker is alive.
After 30 seconds without progress, it explains a possible network/file wait;
after 120 seconds it labels a possible stall, not a confirmed failure. Browser
polling times out after 5 seconds and does not accumulate overlapping requests.
Cancel acknowledges immediately; an OS/network read may need to return first.
Existing safe-copy, approval, source-integrity and partial-folder rules remain.
